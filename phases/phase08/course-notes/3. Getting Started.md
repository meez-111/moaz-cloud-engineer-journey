## 1. Creating an AWS Account

To start using AWS, you need to create an account. Here's the process:

| Step | Action |
|------|--------|
| 1 | Go to [aws.amazon.com](https://aws.amazon.com) and click **Create an AWS Account**. |
| 2 | Enter your email address, account name, and a strong password. |
| 3 | Choose **Root user** (this is the first user created). |
| 4 | Enter your contact information (business or personal). |
| 5 | Provide a valid payment method (credit/debit card) – AWS requires this even for the Free Tier. |
| 6 | Verify your phone number (SMS or voice call). |
| 7 | Choose a support plan (Basic is free and included). |
| 8 | Wait for your account to be activated (usually within minutes). |

> **Important:** AWS will charge a small, refundable amount (e.g., $1) to verify your payment method. This is temporary and is typically reversed within a few days.

## 2. The AWS Root User – Why You Shouldn't Use It

The **root user** is the first user created when you sign up for AWS. It has **unrestricted access** to all resources and billing.

| Characteristic | Root User |
|----------------|-----------|
| **Access** | Full, unrestricted access to all services and billing. |
| **Can it be restricted?** | No – the root user always has full access. |
| **Best practice** | **Do not use** the root user for day‑to‑day activities. |
| **What to do instead** | Create **IAM users** with limited permissions and use them for daily operations. |
| **When to use root user** | Only for account‑level tasks: changing support plans, closing the account, or managing root user MFA. |

**Why this matters:** If your root user credentials are compromised, an attacker has full control of your AWS account and can run up massive bills or delete resources. Use IAM users with the **principle of least privilege** instead.

## 3. Creating an IAM User (Administrative)

IAM (Identity and Access Management) allows you to create users, groups, and roles with specific permissions.

### Step‑by‑Step: Create an Admin IAM User

1. Log in to the AWS Management Console as the **root user**.
2. Go to **IAM** (Identity and Access Management) in the AWS Console.
3. In the left navigation pane, click **Users** → **Add users**.
4. Enter a username (e.g., `admin`).
5. Select **Provide user access to the AWS Management Console**.
6. Choose **I want to create an IAM user**.
7. Set a password (choose **Autogenerated password** or **Custom password**).
8. Uncheck **User must create a new password at next sign‑in** (or leave checked for security).
9. Click **Next**.
10. Attach the **AdministratorAccess** policy (or use a group with this policy).
11. Review and click **Create user**.
12. Download the `.csv` file with the user's credentials (password and sign‑in URL).

**Login URL:**  
`https://<your-account-id>.signin.aws.amazon.com/console`

> **Best practice:** Create a group `Admins` with `AdministratorAccess` and add users to that group. This scales better.

**Alternative – IAM Identity Center (formerly SSO):** For larger organisations, use IAM Identity Center to manage access across multiple accounts.

## 4. AWS Region Selector – Choosing a Region

When you work with services like EC2, S3, RDS, you must select a **Region**. Not all services are available in all Regions.

| Factor | Why It Matters |
|--------|----------------|
| **Latency** | Choose the Region closest to your users to minimise latency. |
| **Services** | Some services are available only in specific Regions (e.g., certain AI/ML services). |
| **Cost** | Pricing varies by Region (e.g., `us-east-1` is often cheaper than `ap-southeast-1`). |
| **Compliance** | Data residency laws (e.g., GDPR, Saudi PDPL) may require data to stay within a specific country. |
| **Service availability** | New services often launch first in `us-east-1` (N. Virginia). |

**Recommended Region for beginners:** `us-east-1` (N. Virginia) – it has the most services and is often the cheapest.

**Global Services (not Region‑specific):**
- **IAM** (Identity and Access Management)
- **CloudFront** (CDN)
- **Route 53** (DNS)
- **WAF** (Web Application Firewall)
- **S3** (buckets are global, but data is stored in the selected Region)

## 5. The Overbilling Story – A Cautionary Tale

**The Story:** A developer accidentally left a large EC2 instance running for several days. The bill at the end of the month was thousands of dollars. The developer had not set up budgets, billing alarms, or monitoring, so they had no idea until the bill arrived.

**How to avoid this:**

- Set up **AWS Budgets** (see section 6).
- Create **Billing Alarms** (see section 8).
- Tag resources and use **Cost Explorer** to monitor spending.
- Use **AWS Config** to enforce policies (e.g., "no `m5.8xlarge` in dev accounts").
- Enable **Cost Allocation Tags** to track spending per project.

> **Cloud engineers' rule:** Always clean up resources after testing. Stop or terminate EC2 instances, delete unused S3 buckets, and review your bill regularly.

## 6. AWS Budgets – Prevent Unexpected Bills

**AWS Budgets** allow you to set spending thresholds and get alerts when you're approaching them.

| Budget Type | Description |
|-------------|-------------|
| **Cost Budget** | Tracks your total spending (e.g., $100 per month). |
| **Usage Budget** | Tracks usage of a specific service (e.g., 10,000 S3 PUT requests). |
| **Reservation Budget** | Tracks your Reserved Instance utilisation. |
| **Savings Plans Budget** | Tracks Savings Plans commitment utilisation. |

**Setting up a budget:**

1. Go to **AWS Budgets** in the AWS Console.
2. Click **Create budget**.
3. Choose **Cost budget** (or the type you need).
4. Set the budget amount (e.g., $10/month).
5. Set an alert threshold (e.g., 80% → send notification, 100% → send notification).
6. Enter the email address where you want to receive alerts.
7. Click **Create**.

> **Tip:** Set up a **$10/month budget** when you first start. It will alert you if you're about to exceed a reasonable amount.

## 7. AWS Free Tier – What's Included

The **AWS Free Tier** allows you to try services for free within certain limits. It's perfect for learning, testing, and prototyping.

| Service | Free Tier Limit | Duration |
|---------|-----------------|----------|
| **EC2 (t2.micro / t3.micro)** | 750 hours per month | 12 months |
| **S3 (Standard)** | 5 GB of storage, 20,000 GET requests | 12 months |
| **RDS (db.t2.micro)** | 750 hours per month | 12 months |
| **Lambda** | 1 million requests per month | Permanent |
| **CloudFront** | 50 GB data transfer out, 2,000,000 HTTP/HTTPS requests | 12 months |
| **DynamoDB** | 25 GB of storage, 25 read/write capacity units | Permanent |

> **Important:** The Free Tier is **per account**, not per user. If you create multiple accounts, each gets its own Free Tier limits.

**Always check the Free Tier limits before using a service** – accidentally exceeding limits can result in unexpected charges.

## 8. Billing Alarms – Get Notified Before You Spend Too Much

**Billing Alarms** use CloudWatch to send notifications when your estimated charges exceed a threshold.

**Setting up a billing alarm:**

1. Go to **CloudWatch** in the AWS Console.
2. Select **Alarms** → **All alarms** → **Create alarm**.
3. Click **Select metric** → **Billing** → **Total Estimated Charge** → select the metric.
4. Choose the metric **EstimatedCharges**.
5. Set the threshold (e.g., `> 10 USD`).
6. Configure the action (e.g., send a notification to an SNS topic with your email).
7. Name the alarm (e.g., `BillingAlarm-10USD`).
8. Click **Create alarm**.

**Billing Alarm vs. Budget:**
| Feature | Billing Alarm | Budget |
|---------|---------------|--------|
| **Granularity** | Hourly (estimated charges) | Daily (actual charges) |
| **Use case** | Near‑real‑time alerting | Budget forecasting and planning |
| **When to use** | To catch unexpected spikes quickly | To track monthly spending |

**Best practice:** Set up **both** – a billing alarm for real‑time alerts and a budget for monthly planning.

## 9. Turning on MFA (Multi‑Factor Authentication)

**MFA** adds an extra layer of security to your AWS account. Even if someone has your password, they cannot log in without the MFA code from your device.

**MFA devices supported by AWS:**

| Device Type | Description |
|-------------|-------------|
| **Virtual MFA** | Use an authenticator app (Google Authenticator, Microsoft Authenticator, Authy) on your phone. |
| **U2F Security Key** | Physical security key (YubiKey) that plugs into USB‑C or USB‑A. |
| **Hardware TOTP Token** | Standalone hardware device that generates TOTP codes. |

**Enable MFA on your root user (critical):**

1. Log in as the **root user**.
2. Go to **IAM** → **Users** → **Security credentials**.
3. Find **Multi‑factor authentication (MFA)** and click **Assign MFA device**.
4. Choose **Virtual MFA device** (most common).
5. Install an authenticator app on your phone (Google Authenticator, etc.).
6. Scan the QR code or enter the setup key manually.
7. Enter two consecutive MFA codes to verify.
8. Click **Assign MFA**.

**Enable MFA for IAM users (best practice):**

1. As an admin, go to **IAM** → **Users** → select the user.
2. Click **Security credentials** → **Assign MFA device**.
3. Follow the same steps as above.

> **Security best practice:** **Always enable MFA on your root user.** Without MFA, your account is at risk of compromise.

## 11. Practice Lab – Verify Your Understanding

1. **Create your AWS account:**
   - Follow the sign‑up process. Enter your payment details (required even for Free Tier).

2. **Create an IAM admin user:**
   - Log in as root → go to IAM → create a user with `AdministratorAccess`.
   - Log out of root and log in as the new IAM user.

3. **Set up a budget:**
   - Create a budget for $10/month with an alert at 80%.

4. **Set up a billing alarm:**
   - Create a billing alarm for $10 estimated charges.

5. **Enable MFA on root user:**
   - Set up MFA on your root user (use Google Authenticator or a similar app).

6. **Explore the Free Tier:**
   - Go to the AWS Console → Billing → Free Tier. Review the services you can use for free.

7. **Choose your Region:**
   - Select `us-east-1` as your default Region.
