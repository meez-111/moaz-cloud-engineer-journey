## 1. AWS API – The Foundation of Everything

The **AWS API** is the core interface through which all AWS services are controlled. Every AWS service exposes a set of API operations that allow you to create, read, update, and delete resources.

**How you interact with the AWS API:**

| Interface | Description |
|-----------|-------------|
| **Management Console** | Web UI – graphical interface to the API. |
| **AWS CLI** | Command‑line tool – uses the API behind the scenes. |
| **AWS SDK** | Programming libraries (Python, Java, JavaScript, etc.) – wrap the API. |
| **CloudShell** | Browser‑based CLI – also uses the API. |
| **Third‑party tools** | Terraform, Ansible, Pulumi – all use the AWS API. |

```
+------------------+     +------------------+     +------------------+
|   Management     |     |     AWS CLI      |     |    AWS SDK       |
|   Console        |     |                  |     |                  |
|   (Web UI)       |     |   (Command Line) |     |   (Programming)  |
+------------------+     +------------------+     +------------------+
         │                        │                         │
         └────────────────────────┼─────────────────────────┘
                                  │
                                  ▼
                       ┌─────────────────────┐
                       │     AWS API         │
                       │  (HTTPS / REST)     │
                       └─────────────────────┘
                                  │
                                  ▼
                       ┌─────────────────────┐
                       │   AWS Services      │
                       │   (EC2, S3, RDS…)   │
                       └─────────────────────┘
```

**API authentication:** Every API call must be authenticated using:
- **IAM access keys** (Access Key ID + Secret Access Key).
- **IAM roles** (for EC2 instances, Lambda, etc.).
- **AWS credentials** (from environment variables, configuration files, or IAM instance profiles).

## 2. AWS Management Console (Web UI)

The **AWS Management Console** is a web‑based graphical user interface for accessing and managing AWS services.

**Features:**

| Feature | Description |
|---------|-------------|
| **Dashboard** | Home page with recent services, AWS Health, and billing information. |
| **Service search** | Quickly find services by name. |
| **Region selector** | Choose which Region you want to work in. |
| **Global navigation** | IAM, CloudFront, Route 53 (global services) are always available. |
| **Dark mode** | Toggle between light and dark themes. |
| **Mobile app** | AWS Console mobile app for iOS and Android. |

**Best practices:**
- Use the **search bar** to find services quickly.
- Use **Tags** to organise resources (e.g., `Environment:Production`).
- Use **Resource Groups** to view resources by project/team.

**Exam tip:** The Management Console is **not** used for automation – use CLI or SDK for scripting.

## 3. Service Console (Per‑Service UI)

Each AWS service has its own **service console** – a dedicated UI within the Management Console.

| Service | Service Console Features |
|---------|--------------------------|
| **EC2** | Launch instances, manage security groups, view metrics. |
| **S3** | Create buckets, upload/download objects, set permissions. |
| **IAM** | Create users, groups, roles, and policies. |
| **RDS** | Launch and manage databases, configure backups. |
| **VPC** | Create VPCs, subnets, route tables, internet gateways. |

**Navigation:** From the Management Console home, search for the service name and click on it.

## 4. AWS Account ID

The **AWS Account ID** is a unique 12‑digit number assigned to your AWS account.

| Aspect | Description |
|--------|-------------|
| **Format** | 12 digits (e.g., `123456789012`). |
| **Use** | Used for resource naming, cross‑account access, and IAM policies. |
| **Where to find** | Top‑right corner of the AWS Management Console. |
| **Example ARN** | `arn:aws:iam::123456789012:user/admin` |

**Why it matters:**
- Required for **cross‑account IAM roles**.
- Used in **ARNs** to identify resources.
- Needed for **AWS Organizations** and **Consolidated Billing**.

## 5. AWS Tools for PowerShell

**AWS Tools for PowerShell** is a set of PowerShell modules that allow you to manage AWS resources from the PowerShell command line.

| Aspect | Description |
|--------|-------------|
| **Supported platforms** | Windows, macOS, Linux (PowerShell Core). |
| **Module name** | `AWSPowerShell.NetCore` (cross‑platform) or `AWSPowerShell` (Windows‑only). |
| **Commands** | Use `Get-EC2Instance`, `New-S3Bucket`, etc. |
| **Installation** | `Install-Module -Name AWSPowerShell.NetCore -Force` |

**Example:**
```powershell
# List all EC2 instances
Get-EC2Instance

# Create an S3 bucket
New-S3Bucket -BucketName my-bucket
```

## 6. Amazon Resource Names (ARNs)

An **ARN (Amazon Resource Name)** is a unique identifier for any AWS resource. It is used to specify resources in IAM policies, service APIs, and cross‑service interactions.

**ARN Format:**

```
arn:partition:service:region:account-id:resource-type/resource-id
```

| Component | Example | Meaning |
|-----------|---------|---------|
| `arn` | – | ARN prefix. |
| `partition` | `aws` | Partition (AWS standard). Other partitions: `aws-cn` (China), `aws-us-gov` (GovCloud). |
| `service` | `s3` | AWS service (e.g., `s3`, `ec2`, `iam`). |
| `region` | `us-east-1` | Region (not required for all services). |
| `account-id` | `123456789012` | AWS account ID. |
| `resource-type/resource-id` | `bucket/my-bucket` | Resource identifier. |

**Examples:**

| Resource | ARN |
|----------|-----|
| IAM user | `arn:aws:iam::123456789012:user/admin` |
| S3 bucket | `arn:aws:s3:::my-bucket` |
| EC2 instance | `arn:aws:ec2:us-east-1:123456789012:instance/i-1234567890abcdef0` |
| RDS instance | `arn:aws:rds:us-east-1:123456789012:db:my-database` |
| Lambda function | `arn:aws:lambda:us-east-1:123456789012:function:my-function` |

## 7. AWS CLI – Command Line Interface

The **AWS CLI (Command Line Interface)** is a unified tool for managing AWS services from the command line. It is available for Windows, macOS, and Linux.

| Aspect | Description |
|--------|-------------|
| **Installation** | `curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip" && unzip awscliv2.zip && sudo ./aws/install` |
| **Configuration** | `aws configure` – sets Access Key ID, Secret Access Key, Region, and Output Format. |
| **Default Region** | `us-east-1` (or your preferred Region). |
| **Output formats** | `json`, `yaml`, `text`, `table`. |

**Common commands:**

| Command | Description |
|---------|-------------|
| `aws s3 ls` | List S3 buckets. |
| `aws s3 sync` | Sync local directory with S3 bucket. |
| `aws ec2 describe-instances` | List EC2 instances. |
| `aws iam list-users` | List IAM users. |
| `aws rds describe-db-instances` | List RDS databases. |
| `aws help` | Show help for all commands. |

**Example – List EC2 instances:**

```bash
aws ec2 describe-instances --region us-east-1 --output table
```

**CLI best practices:**
- Use **IAM access keys** (not root user keys).
- Use **profiles** for multiple accounts:
  ```bash
  aws configure --profile myaccount
  aws s3 ls --profile myaccount
  ```
- Use **`--dry-run`** to validate commands without executing them.

## 8. AWS SDK – Software Development Kits

**AWS SDKs** are programming libraries that allow you to interact with AWS services from your code.

| Language | SDK | Example Use Case |
|----------|-----|------------------|
| **Python** | `boto3` | Automate EC2, S3, Lambda from Python scripts. |
| **JavaScript / Node.js** | `aws-sdk` | Build serverless applications with Lambda and API Gateway. |
| **Java** | `aws-java-sdk` | Enterprise applications on AWS. |
| **Go** | `aws-sdk-go` | Cloud‑native applications in Go. |
| **.NET (C#)** | `AWSSDK` | Windows applications on AWS. |
| **PHP** | `aws-sdk-php` | Web applications. |
| **Ruby** | `aws-sdk-ruby` | Ruby on Rails applications. |

**Example – Python with boto3:**

```python
import boto3

# Create EC2 client
ec2 = boto3.client('ec2', region_name='us-east-1')

# List all instances
response = ec2.describe_instances()
for reservation in response['Reservations']:
    for instance in reservation['Instances']:
        print(instance['InstanceId'], instance['State']['Name'])
```

## 9. AWS CloudShell – In‑Browser CLI

**AWS CloudShell** is a browser‑based, pre‑authenticated shell environment that runs in the AWS Management Console.

| Aspect | Description |
|--------|-------------|
| **Access** | Available from the AWS Management Console (top bar). |
| **Features** | Pre‑installed AWS CLI, Python, Node.js, Git, Docker. |
| **Authentication** | Automatically uses your AWS credentials (no need to configure `aws configure`). |
| **Storage** | 1 GB of persistent storage (`/home/cloudshell-user`). |
| **Use cases** | Quick CLI commands, testing scripts, debugging. |

**Example:** You can run `aws s3 ls` from CloudShell without installing the CLI or configuring credentials.

**Limitations:**
- Not available in all Regions.
- Limited memory and CPU (not suitable for heavy workloads).

## 10. Infrastructure as Code (IaC)

**Infrastructure as Code (IaC)** is the practice of managing and provisioning infrastructure using code (configuration files) rather than manual processes.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Automate infrastructure deployment, reduce human error, enable version control. |
| **Approaches** | **Declarative** – define the desired state, the tool makes it happen. **Imperative** – define the exact steps to achieve the desired state. |
| **AWS IaC tools** | AWS CloudFormation, AWS CDK, Terraform, Pulumi, Ansible. |

**Benefits of IaC:**

| Benefit | Description |
|---------|-------------|
| **Repeatability** | Deploy the same infrastructure multiple times consistently. |
| **Version control** | Track changes in Git. |
| **Automation** | Integrate with CI/CD pipelines. |
| **Reduced errors** | No manual misconfigurations. |
| **Auditability** | Know who changed what and when. |

## 11. AWS CloudFormation – Declarative IaC

**AWS CloudFormation** is AWS's native Infrastructure as Code service. It allows you to define your infrastructure in **JSON or YAML** templates.

| Aspect | Description |
|--------|-------------|
| **Approach** | Declarative – you describe the desired state (resources, dependencies, configurations). |
| **Templates** | JSON or YAML files. |
| **Stacks** | A collection of resources deployed from a single template. |
| **StackSets** | Deploy stacks across multiple accounts and Regions. |
| **Drift detection** | Detect if resources have changed outside of CloudFormation. |
| **Change sets** | Preview changes before applying them. |

**Example CloudFormation template (YAML):**

```yaml
Resources:
  MyEC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: t2.micro
      ImageId: ami-0c55b159cbfafe1f0
      KeyName: my-key-pair
      SecurityGroups:
        - !Ref InstanceSecurityGroup

  InstanceSecurityGroup:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: Allow SSH and HTTP
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 22
          ToPort: 22
          CidrIp: 0.0.0.0/0
        - IpProtocol: tcp
          FromPort: 80
          ToPort: 80
          CidrIp: 0.0.0.0/0
```

## 12. AWS CDK – Infrastructure as Code with Programming Languages

The **AWS Cloud Development Kit (CDK)** allows you to define infrastructure using familiar programming languages like Python, TypeScript, Java, C#, and Go.

| Aspect | Description |
|--------|-------------|
| **Approach** | Imperative – you write code that generates CloudFormation templates. |
| **Supported languages** | TypeScript, Python, Java, C#, Go (currently in preview for Go). |
| **Constructs** | Reusable cloud components (L1, L2, L3 constructs). |
| **Synth** | Converts your code into a CloudFormation template. |
| **Deploy** | Deploys the synthesized template. |

**Example – AWS CDK (Python):**

```python
from aws_cdk import (
    Stack,
    aws_ec2 as ec2,
    aws_s3 as s3,
)
from constructs import Construct

class MyStack(Stack):
    def __init__(self, scope: Construct, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)

        # Create an S3 bucket
        bucket = s3.Bucket(self, "MyBucket",
            versioned=True,
            encryption=s3.BucketEncryption.S3_MANAGED
        )

        # Create an EC2 instance
        instance = ec2.Instance(self, "MyInstance",
            instance_type=ec2.InstanceType("t2.micro"),
            machine_image=ec2.MachineImage.latest_amazon_linux2(),
        )
```

## 14. Access Keys – Programmatic Access

**Access Keys** are credentials used to authenticate API calls from the CLI, SDK, or other tools.

| Component | Description |
|-----------|-------------|
| **Access Key ID** | A 20‑character alphanumeric identifier (e.g., `AKIAIOSFODNN7EXAMPLE`). |
| **Secret Access Key** | A 40‑character secret key (e.g., `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`). |
| **Purpose** | Used to sign API requests (AWS Signature V4). |
| **Best practice** | Never share your Secret Access Key. Use IAM roles instead of long‑term keys when possible. |

**Creating access keys:**

1. Go to **IAM** → **Users** → select a user.
2. Click **Create access key**.
3. Choose the use case (CLI, SDK, or EC2).
4. Download the `.csv` file with the credentials (this is the only time you can see the Secret Access Key).

**Security best practices:**
- Do **not** hard‑code keys in your source code.
- Use **IAM roles** for EC2 instances, Lambda functions, and other AWS services.
- Rotate keys regularly.
- Use **AWS Secrets Manager** or **Parameter Store** to store secrets.
- Remove unused access keys.

## 17. Practice Lab – Verify Your Understanding

   (`arn:aws:s3:::my-bucket`)

   Install AWS CDK and create a simple stack with an S3 bucket using Python or TypeScript.
