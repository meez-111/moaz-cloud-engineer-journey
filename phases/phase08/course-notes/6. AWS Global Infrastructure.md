## 1. AWS Global Infrastructure Overview

The **AWS Global Infrastructure** is the physical backbone of Amazon Web Services. It is designed to provide high availability, low latency, and fault tolerance for cloud applications.

| Component | Count (as of 2025) |
|-----------|-------------------|
| **Regions** | 37 |
| **Availability Zones (AZs)** | 107+ |
| **Direct Connect Locations** | 120+ |
| **Points of Presence (PoPs)** | 550+ |

The infrastructure is organised hierarchically: **Regions** contain **Availability Zones**, and **Edge Locations** (PoPs) are distributed globally to serve content closer to users.

---

## 2. Regions

### 2.1 What is a Region?

A **Region** is a distinct geographical area that contains multiple **Availability Zones**. Each Region is physically isolated from other Regions and has its own power, cooling, and networking infrastructure.

**Key points:**
- Regions are **completely independent** – data does not automatically replicate between Regions.
- Not all services are available in all Regions.
- Pricing varies by Region.

**Examples of Regions:**
- `us-east-1` – N. Virginia, USA
- `us-west-2` – Oregon, USA
- `eu-west-1` – Ireland
- `ap-southeast-2` – Sydney, Australia
- `me-south-1` – Bahrain (important for KSA/ME customers)

### 2.2 The Special Case of `us-east-1`

`us-east-1` (N. Virginia) is the **oldest and most mature** AWS Region.

| Reason | Why `us-east-1` is special |
|--------|----------------------------|
| **First Region** | Launched in 2006 – it has the most services. |
| **Lowest cost** | Often the cheapest Region (pricing benchmark). |
| **New services first** | AWS often launches new services in `us-east-1` first. |

**Exam tip:** When a new AWS service is announced, it is almost always available in `us-east-1` first.

### 2.3 Factors for Choosing a Region

| Factor | Why It Matters |
|--------|----------------|
| **Latency** | Choose the Region closest to your users to reduce network latency. |
| **Services** | Not all services are available in all Regions. |
| **Cost** | Pricing varies by Region (e.g., `us-east-1` is often cheaper). |
| **Compliance** | Data residency laws (GDPR, Saudi PDPL) may require data to stay within a specific country. |

### 2.4 Region Representation in Diagrams

In AWS architecture diagrams, a Region is typically represented as:

```
┌─────────────────────────────────────────────────────────────┐
│                     AWS Region (us-east-1)                 │

```

## 3. Regions vs. Global Services

| Service Type | Description | Examples |
|--------------|-------------|----------|
| **Regional Services** | Run in a specific Region. You must select a Region. | EC2, S3, RDS, Lambda, VPC |
| **Global Services** | Are not tied to a specific Region. Available globally. | IAM, CloudFront, Route 53, WAF, AWS Organizations |

**Important:** S3 buckets are global by name, but data is stored in the selected Region.

## 4. Availability Zones (AZs)

### 4.1 What is an Availability Zone?

An **Availability Zone** is one or more data centres within a Region. Each AZ has:

- **Independent power**, cooling, and networking.
- **Redundant connectivity** to other AZs in the same Region.
- Designed for **fault isolation** – if one AZ fails, others remain operational.

**Key points:**
- AZs are physically separated (usually miles apart).
- Inter‑AZ latency is very low (single‑digit milliseconds).
- Most Regions have **3 AZs** (minimum 2).

**Example:** `us-east-1a`, `us-east-1b`, `us-east-1c` are separate AZs in the `us-east-1` Region.

## 5. Fault Tolerance and High Availability

| Term | Definition | AWS Implementation |
|------|------------|---------------------|
| **Fault Tolerance** | System continues operating even when a component fails. | Multi‑AZ deployments, load balancing, health checks. |
| **High Availability (HA)** | Minimises downtime; system is operational most of the time. | Auto Scaling, RDS Multi‑AZ, ELB. |

**Multi‑AZ architecture example:**

```
            Internet
                │
          ┌─────┴─────┐
          │  ALB/ELB  │
          └─────┬─────┘
                │
    ┌───────────┼───────────┐
    │           │           │
┌───▼───┐  ┌───▼───┐  ┌───▼───┐
│ EC2   │  │ EC2   │  │ EC2   │
│ AZ-1a │  │ AZ-1b │  │ AZ-1c │
└───────┘  └───────┘  └───────┘
```

If an entire AZ fails, the load balancer routes traffic to the remaining AZs.

## 6. AWS Global Network

The **AWS Global Network** is the high‑speed, private backbone connecting all AWS Regions and data centres.

**Analogy:** It's like an expressway where data can move very fast between data centres.

| Component | Description |
|-----------|-------------|
| **Edge Locations** | Act as on‑ramps and off‑ramps to the AWS Global Network. |
| **AWS Global Accelerator** | Uses edge locations as an on‑ramp to accelerate traffic. |
| **S3 Transfer Acceleration** | Uses edge locations for faster uploads to S3. |
| **CloudFront** | Uses edge locations as an off‑ramp to cache content near end users. |
| **VPC Endpoints** | Ensure your resources stay within the AWS network and do not traverse the public internet. |

---

## 7. Points of Presence (PoPs)

A **Point of Presence (PoP)** is an intermediate location between an AWS Region and the end user. It could be a data centre or a collection of hardware.

**AWS PoP resources include:**

- **Edge Locations** – used by CloudFront and Global Accelerator.
- **Regional Edge Caches** – larger caches that sit between Edge Locations and the origin.

### 7.1 Edge Locations

- Used by **CloudFront** to cache content closer to users.
- Hundreds of edge locations worldwide.
- Not tied to a specific Region.

### 7.2 Regional Edge Caches

- Sit between Edge Locations and the origin.
- Cache content that is not popular enough to be stored at edge locations.
- Larger storage capacity than edge locations.

---

## 8. Tier 1 Network

**Tier 1** refers to the highest level of network providers that have global reach and do not pay for peering. AWS has its own Tier 1‑like global network.

**Why it matters:**
- AWS's private backbone provides **lower latency** and **higher reliability** than the public internet.
- Data travels over **AWS‑owned fibre** between Regions.
- This is why AWS can guarantee high performance for services like S3 Transfer Acceleration and Global Accelerator.

---

## 9. AWS Services Using PoPs

### 9.1 Amazon CloudFront

**Purpose:** CDN (Content Delivery Network) – caches content at edge locations to reduce latency.

**How it works:**
1. User requests content (e.g., a video file).
2. CloudFront serves it from the nearest edge location.
3. If not cached, it fetches from the origin and caches it.

### 9.2 AWS S3 Transfer Acceleration

**Purpose:** Speeds up uploads to S3 by using edge locations as an on‑ramp to the AWS Global Network.

**Use case:** Large file uploads from geographically distributed users.

### 9.3 AWS Global Accelerator

**Purpose:** Improves performance and availability of applications by directing traffic through the AWS Global Network.

**How it works:**
1. Global Accelerator provides two static IP addresses.
2. Traffic enters the AWS network at the nearest edge location.
3. Travels across the AWS backbone to the endpoint.

## 10. AWS Direct Connect

**Direct Connect** is a private, dedicated connection between your on‑premises data centre and AWS.

| Aspect | Description |
|--------|-------------|
| **Bandwidth** | 1 Gbps, 10 Gbps, 100 Gbps. |
| **Network** | Private, not over the public internet. |
| **Use cases** | Hybrid cloud, large data transfers, lower latency workloads. |
| **Cost** | Fixed monthly cost per port + data transfer fees. |

**Alternatives:** VPN (over the public internet) – cheaper but less reliable.

---

## 11. Local Zones

**Local Zones** are extensions of an AWS Region that place compute, storage, database, and other services closer to end users.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Reduce latency for latency‑sensitive applications (e.g., gaming, media, machine learning). |
| **Location** | In a metropolitan area near a Region. |
| **Services** | EC2, EBS, VPC, ELB, etc. |
| **Example** | `us-west-2-lax-1a` (Los Angeles). |

**Use case:** A gaming company needs sub‑5ms latency for users in Los Angeles. They deploy in the LA Local Zone.

---

## 12. Wavelength Zones

**Wavelength Zones** embed AWS compute and storage services at the edge of 5G networks.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Ultra‑low latency for 5G applications. |
| **Location** | Inside 5G network providers' data centres. |
| **Use cases** | Augmented/virtual reality, autonomous vehicles, industrial IoT. |
| **Partners** | Verizon, Vodafone, KDDI, SK Telecom. |

**Analogy:** Wavelength Zones bring the cloud to the 5G network, not the other way around.

---

## 13. Data Residency

**Data residency** refers to where data is physically stored.

| Aspect | Description |
|--------|-------------|
| **Regulatory compliance** | GDPR, Saudi PDPL, HIPAA require data to stay in specific countries. |
| **AWS solution** | Choose the appropriate Region for your data. |
| **Example** | For Saudi users, data can be stored in `me-south-1` (Bahrain). |

**Architecture patterns for data residency:**
- **Data localisation:** Keep data in a specific Region.
- **Data replication:** Replicate data across Regions for DR (with compliance).

---

## 14. AWS for Government – GovCloud

**GovCloud (US) Regions** are designed for US government agencies and contractors.

| Aspect | Description |
|--------|-------------|
| **Compliance** | FedRAMP, FIPS, ITAR, CJIS. |
| **Access** | Only US persons (citizens or green card holders) can access. |
| **Regions** | `us-gov-west-1` (Oregon), `us-gov-east-1` (Virginia). |
| **Services** | Most AWS services are available in GovCloud. |

**Equivalent in other countries:** AWS has partner agreements for sovereign clouds (e.g., AWS Cloud for European Sovereignty).

## 15. AWS in China

AWS has a **unique** presence in China:

| Aspect | Description |
|--------|-------------|
| **Operator** | AWS China is operated by **Sinnet** (in Beijing) and **NWH** (in Ningxia). |
| **Account** | You must create a separate AWS China account (not the same as global AWS account). |
| **Services** | Limited compared to global Regions. |
| **Compliance** | Must comply with Chinese data laws. |

**Why this matters:** If you have customers in China, you need to use AWS China Regions.

## 17. AWS Ground Station

**AWS Ground Station** is a managed service that controls satellite communications.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Download data from satellites, process it in the cloud. |
| **Integration** | Works with S3, EC2, SageMaker, etc. |
| **Use cases** | Weather monitoring, agriculture, telecommunications. |
| **Ground stations** | Located globally near AWS Regions. |

**Example:** A satellite company uses AWS Ground Station to download weather data and process it with SageMaker for ML predictions.

---

## 18. AWS Outposts

**AWS Outposts** is a managed service that brings AWS infrastructure and services to your on‑premises data centre.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Run AWS services locally, on‑premises. |
| **What you get** | A physical rack of compute/storage hardware shipped to your site. |
| **Services** | EC2, EBS, RDS, ECS, EKS, S3 (local). |
| **Management** | AWS manages the hardware and services remotely. |

**Use cases:**
- **Low latency:** Applications that need single‑digit millisecond latency.
- **Data residency:** Data that cannot leave the on‑premises environment.
- **Hybrid cloud:** Run part of the application on‑premises and part in the cloud.

**Example:** A factory uses AWS Outposts to run IoT analytics locally while using AWS Region for long‑term storage.

   You are building an application for users in the Middle East. Which Region should you choose? (Consider `me-south-1` – Bahrain.)
